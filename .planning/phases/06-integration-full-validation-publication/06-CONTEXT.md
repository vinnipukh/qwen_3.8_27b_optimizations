<decisions>
## Implementation Decisions

### Execution protocol & budget (owner-agreed 2026-08-25)
- **Time envelope:** ~3–6h wall-clock, ~1–2h hands-on. 06-01+06-03 ≈ 30–45min; final matrix ≈ 60–120min; full QUAL-02 ≈ 10–15min; publication ≈ 30min.
- **Smoke-first:** run `run_session.py --tiers 4096 --repeats 3` (~15min) to prove the custom build survives e2e BEFORE committing to the full 3-tier session.
- **Serial-last:** only the final matrix requires one supervised GPU session; everything else parallelizable with doc drafting.

### Integration (INTEG-01)
- **Quilt, not fork:** `patches/*.patch` (`git apply`) additive over pinned `bb4caa75` — `build-stock` (OFF) vs `build-custom` (ON) from one tree. Mirrors upstream CMake `option()` pattern [llama.cpp #5966] but keeps bisectable overlay per ROADMAP anti-fork note.
- **Wave32 pin:** `CMAKE_HIP_ARCHITECTURES=gfx1100` only, `__launch_bounds__(256,4)` ≤96 VGPR, `amdgpu_flat_work_group_size(256,256)`. No fat binary.
- **Dispatch:** `custom_gfx1100/{gemv,gemm}.cuh` vendoring `kernels/matmul_iq4xs/` (TILE_M=16 + `B_lds[2][32][33]` + WMMA) — `mmq/mvq` intercept only when `can_handle` (canonical `5120×5120`/`5120×17408`/`17408×5120`, `M=1` vs `M≥16`).
- **Empty-flag first:** 06-01 builds OFF vs ON with no-op dispatch to prove wiring before winner logic lands. OFF must *compile* clean too — the provisional patch currently would NOT (thermos H-4: unguarded `can_handle` calls; see 06-05).
- **Patch regeneration (06-02):** final patches generated by real `git diff` from a patched tree, must pass `git apply --check` against `bb4caa75`; hand-written pseudo-diffs are design specs only. Must resolve ggml `src1 [M,K]` vs kernel `[K,M]` layout mapping. Flag-scoped `-mwavefrontsize32`, not project-wide. Optional arm: true stock MMVQ/MMQ kernel comparison before any headline "beats stock" claim.

### Validation (BENCH↔QUAL, thermal pairing)
- **Thermal pairing discipline:** stock vs custom back-to-back in ONE heat window; HWiNFO records clocks/temps/power per row (record-don't-control); rows outside the window are discarded and re-run — never cold-morning-stock vs hot-afternoon-custom.
- **Harness:** `benchmarks/bin/run_session.py --tiers 4096 8192 16384 --repeats 5 --delay 10` within **one thermal window** (`benchmarks/host/hwinfo_daemon.py` Windows → `fingerprint.py`, record-don't-control). `ROCr` busy-spin `librocdxg#60` noted for `taskset` isolation.
- **Guard:** fail-fast OOM — allocation caps, NO retry loops; RSS guard + preflight VRAM cap per BENCH-03; `32k` tier = documented expected-FAIL under WSL DXG deficit (1.5–3GB under-report) or capped at 24k with rationale, per `BENCH-04`.
- **Gates:** `run_op_gate.py` 21k PASS, `run_model_gate.py --chunks 145` full wiki.test.raw `PPL 6.4271±1% [6.3628,6.4914]` + 6/6 canaries — custom `cosine=1.0` predicts pass but must be re-run paired (the 2-chunk probe is not evidence).
- **Gate-history rule (thermos H-3):** every gate run writes a NEW timestamped result file — never overwrite a historical record (`phase3/model_gate.json` PASS was overwritten by the FAIL probe; keep FAIL artifact + annotate cause + plan re-run).
- **Baseline runtime mode:** HIP graphs stay ON (+19% decode per dispatch_overhead_report); custom kernels attack kernel time (>85% of decode wall-clock), not launch overhead.
- **Env version gate:** re-run environment fingerprints after ANY driver/ROCm change; verify frozen WSL snapshot reference intact before final matrix.
- **Vulkan arm:** e2e Vulkan baseline (BENCH-04) reported alongside; a win over HIP that loses to plain Vulkan is recorded as such (KERN-03).
