## Technical Strategy

### 1. Thread Mapping & Collaborative Block Processing
* In each row of $K$ elements ($K=5120 \rightarrow 20$ super-blocks):
* A group of 8 threads in a Wave32 wavefront processes 1 super-block (256 weights):
  * **Thread 0:** Reads the 8-byte scale header (`d`, `scales_h`, `scales_l`) and broadcasts to threads 1..7 via `__shfl`.
  * **Thread $t \in [0..7]$:** Loads 16 bytes of $qs$ (32 nibbles) via a single 128-bit load instruction (`uint4`).
  * Thread $t$ performs the 32-element multiply-accumulate with activation slice $x[b \cdot 256 + t \cdot 32 .. b \cdot 256 + t \cdot 32 + 31]$ directly in registers.
  * The 8 partial sums are reduced across the 8 threads using 3 butterfly shuffles:
    ```cpp
    sum += __shfl_xor(sum, 1);
    sum += __shfl_xor(sum, 2);
    sum += __shfl_xor(sum, 4);
    ```
* Each Wave32 wavefront (32 threads) processes 4 super-blocks concurrently.
* A threadblock of 256 threads (8 wavefronts) handles 32 super-blocks per step.

### 2. Multi-Row Batching (Row Tiling)
* For large $N$ (e.g. $N=17408$ in FFN Gate/Up), each threadblock processes multiple output rows (e.g. 2 or 4 rows) simultaneously to amortize activation cache hits in L1 / Infinity Cache.
